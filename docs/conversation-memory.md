# 聊天上下文与滚动摘要（1.1.4）

自动回复将当前聊天页与本地已保存历史衔接，通常最多使用最近 60 条双方消息。按连续重叠去重，不删除聊天中真实重复的句子。长消息较多时采用 12,000 字符预算，优先保留最新内容。没有读取或导入过的历史无法凭空补齐；当前版本不会为了补历史自动向上翻页。

联系人记忆开启时，每个联系人还会维护一份滚动摘要。新增至少 12 条已保存消息后，使用配置的模型合并旧摘要与新增记录；每次最多处理 120 条、16,000 字符，摘要最多 1,800 字符。积压历史分批处理，尚未处理的消息不会从数据库删除。摘要记录对方明确资料、近期话题、约定与待办，并区分双方、已确认约定与提议、已回答问题与未解决事项。

摘要调用单独限制为 15 秒预算，失败保留旧摘要和处理进度，10 分钟内不重复尝试。回复仍可使用近期对话和相关旧片段。摘要优先级低于本人填写资料、本轮真实消息与明确更正。

近期记录与摘要都只引用当前联系人。沿用现有的昵称作为联系人键，因此同昵称或改昵称的识别限制依然存在。本人自动发送的内容会在摘要输入里标为可能的自动回复，不作为对方资料或已证实的本人事实。

“回复与学习”显示滚动摘要数量及已存记录数量。关闭联系人记忆会停用历史补充和摘要引用、更新，当前页仍可提供最多 60 条消息。完整聊天记忆清除会同步删除派生摘要，并使进行中的旧摘要结果失效。原来的 JSON 聊天备份格式继续兼容；备份包含原始记录，滚动摘要可在导入后重新生成。

这会增加部分请求的输入量，并且周期性增加一次摘要模型调用。所选聊天片段与摘要会发送到用户配置的模型接口。模型摘要可能有遗漏或错误；程序要求模型只记录明确内容，并在回复时以原始记录为准。

验证包括 JVM 上下文与摘要策略测试，以及模拟器中使用临时数据库的真实 SQLite 升级、记录保留、联系人隔离、游标推进、失败冷却、重开持久化、清除与并发回写测试。可选模型测试只使用合成对话，不向 Soul 联系人发送消息。
